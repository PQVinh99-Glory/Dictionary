# P07 hybrid parity audit — local code paths, 2026-10-21

The browser `embed-variants-v2` path runs `processLayer1Optical`, extracts spatial DINOv2 patch tokens with `pooling: none`, then `computeSupabase384HybridEmbedding` to 384 dimensions. Pooled CLS output is rejected by `extractDinov2Tokens`. Default camera search sends one RGB probe; gray requires `allowMirror === true` even when the UI passes `includeGray:true`. Worker and server defaults both declare model `onnx-community/dinov2-small`, revision `ef1fb10`, preprocess `kim_canon_v3_letterbox`, and profile `hybrid_gem3_edge_55_45_pseudorgb_u8_v1`. The server rejects supplied vectors with wrong model/version/preprocess/profile/dimension or zero/nonfinite values. Vector RPC fallback keeps the same identity; it cannot reinterpret hybrid as CLS.

This is a code contract audit, not measured browser/index parity. A stale cached worker that produces different pixels under the same declared profile cannot be detected solely by the current label. Exact byte-level browser/reference comparisons and live index asset freshness must be measured after the owner's rebuild stabilizes. No CLS-vs-hybrid accuracy claim is made. P04 did not change descriptor pixels, so no new profile/index version is introduced in this checkpoint.
